Flue QA Agents — architecture

A local, Ollama-backed QA workflow in two phases with a human approval gate between them. Host code sequences every stage; each AI agent runs as its own process, holds only narrow tools, and can write only its own schema- and semantically-validated JSON artifact.

Verified against the source on 2026-09-22: scripts/qa-manual.mjs, scripts/lib/runtime.mjs, src/agents/*.ts (useSkill() / useTool() calls), src/lib/phase1-gate.ts, src/lib/qa-artifacts.ts, package.json.

Retry and recovery

Each Phase 1 stage gets up to 4 attempts. Even attempts continue the same conversation with a correction naming what went wrong; odd attempts start fresh. A stage passes only if its artifact was written during that attempt and re-validates from disk. After the last failed attempt the run stops, keeps what succeeded, and prints npm run qa:manual -- --from <stage>.

Skills — what the badges mean

  • Badges are the skills each agent mounts with useSkill(). Mounting costs one catalog line; the text loads only if the model calls activate_skill.
  • Activated in recorded runs (all agents combined — the run log does not record which agent): product-evidence-policy, test-case-contract, risk-based-testing, test-case-management. Never observed activated: agent-handoff, capability-security, test-planning, ai-test-generation.
  • ⚠ test-case-management: its worked example (user@example.com / Passw0rd!) was copied verbatim into a bad run. Semantic validation blocks it now.

Not runtime skills

  • Vendored but mounted by no agent: ai-bug-triage, ai-qa-review, bug-reproduction, exploratory-testing, qa-project-bootstrap, qa-project-context, selector-drift-recovery, test-reliability.
  • Claude Code operator skills in .claude/skills/ — playwright-cli, mermaid-diagram-skill, diagramming-architecture — and documentation-authoring skills are tooling for the person building this system. No runtime agent loads them.

Experimental — not the default path

npm run qa:agentic runs the QA Manager, which delegates to specialists with useSubagent and lets the model decide the order. It is kept for experiments; the approval gate does not apply to it. Its skills: agent-handoff capability-security product-evidence-policy
